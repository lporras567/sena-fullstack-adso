01

Uvicorn + PostgreSQL nativo en Windows 11

Sin Docker · Sin Nginx · Sin máquina virtual · Todo corre directo en Windows
ACTO 1 · EL PORQUÉ

La opción más directa

Sin Docker ni Nginx, el stack tiene solo dos piezas: PostgreSQL como servicio de Windows y Uvicorn como proceso Python en una PowerShell con el venv activado. Es la configuración más simple posible, ideal para desarrollo local y proyectos de clase.

✅ Cuándo usar esta opción

  • Desarrollo local en tu equipo
  • Proyectos de clase / SENA
  • Aprender FastAPI sin distracciones
  • Equipo sin experiencia en Docker
  • Prototipo rápido en horas

⚠️ Limitaciones a tener en cuenta

  • No escala fácil a producción
  • Sin proxy: solo HTTP, sin HTTPS
  • "Funciona en mi máquina" al colaborar
  • Dependencias instaladas en Windows
  • Para producción: usar Docker (est. 02-04)
ACTO 2 · EL CÓMO

Instalación y configuración

1

Instalar PostgreSQL 16 para Windows

PostgreSQL tiene instalador nativo para Windows. Winget lo instala en un comando. El instalador incluye pgAdmin y el cliente psql.

PowerShell (Administrador) 
# Instalar PostgreSQL 16 con winget
winget install PostgreSQL.PostgreSQL.16

# El instalador pide:
#   Password del superusuario postgres → anotar bien, la necesitarás
#   Port → dejar 5432
#   Locale → dejar por defecto

# Verificar que quedó instalado y corriendo
# (PostgreSQL corre como servicio de Windows automáticamente)
Get-Service postgresql*
# Status: Running

# Verificar con psql
# La ruta puede variar — buscarla:
where.exe psql
# C:\Program Files\PostgreSQL\16\bin\psql.exe

# Conectar como superusuario
psql -U postgres -c "SELECT version();"
# PostgreSQL 16.x on x86_64-windows
2

Crear usuario y base de datos para el proyecto

Buena práctica: nunca usar el superusuario postgres en la aplicación. Crear un usuario dedicado con permisos solo sobre la base de datos del proyecto.

PowerShell 
# Abrir psql como superusuario
psql -U postgres

-- Dentro del prompt psql:
CREATE USER sena_user WITH PASSWORD 'sena_pass_2026';
CREATE DATABASE sena_mvc_db OWNER sena_user;
GRANT ALL PRIVILEGES ON DATABASE sena_mvc_db TO sena_user;
\q

# Verificar conexión con el nuevo usuario
psql -U sena_user -d sena_mvc_db -h localhost -c "SELECT 1 AS ok;"
#  ok
# ----
#   1
3

Clonar el proyecto y crear el entorno virtual

El entorno virtual aísla las dependencias del proyecto de las de otros proyectos Python en tu equipo.

PowerShell 
cd C:\Projects
git clone https://github.com/lporras567/sena_mvc_project.git
cd sena_mvc_project

# Crear y activar el entorno virtual
python -m venv venv
venv\Scripts\activate
# El prompt cambia a: (venv) PS C:\Projects\sena_mvc_project>

# Instalar dependencias
# NOTA: sin Docker usamos psycopg2-binary (síncrono) o asyncpg
pip install fastapi uvicorn sqlalchemy asyncpg greenlet ^
            pydantic[email] passlib[bcrypt] pyjwt python-dotenv
pip freeze > requirements.txt
4

Crear el archivo .env apuntando a PostgreSQL local

La diferencia clave con Docker: DB_HOST es "localhost" porque PostgreSQL corre directamente en Windows, no en un contenedor.

C:\Projects\sena_mvc_project\.env 
# Crear el .env (con VS Code o notepad)
code .env

# Contenido:
DB_USER=sena_user
DB_PASSWORD=sena_pass_2026
DB_HOST=localhost        # ← PostgreSQL nativo en Windows, no un contenedor
DB_PORT=5432
DB_NAME=sena_mvc_db
JWT_SECRET_KEY=clave_local_desarrollo_sena_2026
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
5

Levantar Uvicorn directamente

Sin Nginx, Uvicorn atiende directamente en el puerto 8000. Accedes a la API en http://localhost:8000 y a Swagger en http://localhost:8000/docs.

PowerShell (venv activado) 
# Asegurarse de que el venv está activado
venv\Scripts\activate

# Levantar el servidor
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
# INFO:     Uvicorn running on http://127.0.0.1:8000
# INFO:     Application startup complete.

# --reload recarga automáticamente al guardar cambios en VS Code

# Verificar en el navegador:
Start-Process "http://localhost:8000/docs"
# → Swagger UI

# O desde PowerShell:
Invoke-RestMethod http://localhost:8000/
# mensaje: Backend MVC Asíncrono activo
6

Verificar el ciclo completo sin Docker ni Nginx

La API atiende en :8000, PostgreSQL en :5432, y el frontend Angular (si está compilado) debe servirse aparte con "ng serve" en otro puerto.

PowerShell + navegador 
# En una PowerShell: el backend
uvicorn app.main:app --reload

# En otra PowerShell: el frontend Angular (si aplica)
cd C:\Projects\sena-frontend
ng serve
# → http://localhost:4200

# Probar la API directamente:
Invoke-RestMethod http://localhost:8000/
Invoke-RestMethod http://localhost:8000/usuarios/

# Ver qué está corriendo en los puertos
netstat -ano | findstr ":8000"
netstat -ano | findstr ":5432"

# Detener Uvicorn: Ctrl+C en su PowerShell
# PostgreSQL sigue corriendo como servicio de Windows
7

Gestionar PostgreSQL como servicio de Windows

PostgreSQL se instala como servicio de Windows. Puedes iniciarlo, detenerlo o configurar si arranca automáticamente con el sistema.

PowerShell (Administrador) 
# Ver el estado del servicio
Get-Service postgresql*

# Detener PostgreSQL (liberar recursos cuando no desarrollas)
Stop-Service postgresql-x64-16

# Iniciar PostgreSQL
Start-Service postgresql-x64-16

# Configurar para que NO arranque automáticamente con Windows
Set-Service postgresql-x64-16 -StartupType Manual

# Volver a arranque automático si lo prefieres
Set-Service postgresql-x64-16 -StartupType Automatic

# Script rápido para iniciar todo en un paso:
# (guardar como iniciar-sena-local.ps1)
Start-Service postgresql-x64-16
Set-Location C:\Projects\sena_mvc_project
.\venv\Scripts\Activate.ps1
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
ACTO 3 · RETO

Automatiza el arranque

RETO ESTACIÓN 01

Un solo clic para arrancar todo

Crea un script PowerShell iniciar-sena-local.ps1 que: inicie el servicio de PostgreSQL si no está corriendo, active el venv, levante Uvicorn en una nueva ventana y abra Swagger en el navegador automáticamente. Agrega un acceso directo en el escritorio para ejecutarlo con doble clic.

📂 Ver solución del reto

▼

Script completo iniciar-sena-local.ps1

C:\Projects\sena_mvc_project\iniciar-sena-local.ps1 
# iniciar-sena-local.ps1
# Inicia PostgreSQL + Uvicorn + abre Swagger con un doble clic
# Uso: click derecho → Ejecutar con PowerShell

param(
    [int]$Puerto = 8000,
    [string]$Proyecto = "C:\Projects\sena_mvc_project"
)

Write-Host "Iniciando entorno SENA (sin Docker)..." -ForegroundColor Cyan

# 1. Iniciar PostgreSQL si no está corriendo
$pg = Get-Service postgresql* -ErrorAction SilentlyContinue |
      Where-Object Status -eq 'Running'

if (-not $pg) {
    Write-Host "Iniciando PostgreSQL..." -ForegroundColor Yellow
    Start-Service postgresql-x64-16 -ErrorAction Stop
    Start-Sleep -Seconds 2
}
Write-Host "PostgreSQL OK." -ForegroundColor Green

# 2. Verificar que el puerto no esté ocupado
$ocupado = netstat -ano | findstr ":$Puerto "
if ($ocupado) {
    Write-Host "Puerto $Puerto ocupado. Uvicorn ya corre o hay otro proceso." -ForegroundColor Yellow
    Write-Host $ocupado
} else {
    # 3. Activar venv e iniciar Uvicorn en nueva ventana
    Write-Host "Iniciando Uvicorn en puerto $Puerto..." -ForegroundColor Yellow
    Start-Process powershell -ArgumentList @(
        "-NoExit",
        "-Command",
        "cd '$Proyecto'; .\venv\Scripts\Activate.ps1; uvicorn app.main:app --host 127.0.0.1 --port $Puerto --reload"
    )
    Start-Sleep -Seconds 3
}

# 4. Abrir Swagger en el navegador
Start-Process "http://localhost:$Puerto/docs"
Write-Host "Backend en http://localhost:$Puerto/docs" -ForegroundColor Green

Crear acceso directo en el escritorio

PowerShell 
$WshShell   = New-Object -comObject WScript.Shell
$Shortcut   = $WshShell.CreateShortcut(
    "$env:USERPROFILE\Desktop\SENA Backend Local.lnk"
)
$Shortcut.TargetPath      = "powershell.exe"
$Shortcut.Arguments       = "-ExecutionPolicy Bypass -File C:\Projects\sena_mvc_project\iniciar-sena-local.ps1"
$Shortcut.WorkingDirectory= "C:\Projects\sena_mvc_project"
$Shortcut.Save()
Write-Host "Acceso directo creado." -ForegroundColor Green
